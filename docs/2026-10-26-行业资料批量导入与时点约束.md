# 行业资料批量导入与时点约束

历史候选每天只有少量股票，用它补齐预选母集会留下大量未知行业。扩展资料可使用用户已有授权的数据终端、供应商证券主表或本地行业成分导出文件，一次导入整个股票范围，避免逐票访问公司页面。项目已验证申万官方31张一级行业表的下载与归档；实际覆盖和冲突见[官方行业表采集基准](2026-10-26-官方行业表采集基准.md)。这些表未消除全部冲突，不能视为完整、无歧义的历史证券主表。

## 批量资料格式

`import_industry_mapping.py` 接受 UTF-8 CSV，必需列为 `code,sw_industry,observed_date,source`。代码固定六位并保留前导零。导入者必须显式声明 `--taxonomy sw --taxonomy-version 2021`；`sw_industry` 的第一段必须是现有申万一级行业名称，无法识别时保留未知。其他供应商的同名行业不能仅靠改列名充当申万分类。

运行示例：`python scripts/import_industry_mapping.py --input local-master.csv --output imported-master.json --as-of 2026-10-25 --taxonomy sw --taxonomy-version 2021`。

输出包含原文件 SHA-256、输入路径、每条资料来源、观测日期、显式分类版本、导入覆盖率、逐股票映射和原始观测行。导入覆盖率以资料文件内股票数为分母；实验实际覆盖率必须以评分母集为分母重新计算。

## 时点与冲突

`observed_date` 表示当时已经可获得资料的日期，不能用行业调整生效日期冒充资料发布时间。指定截止日之后的任意记录会拒绝整个导入。相同股票使用最新日期；最新日期的标签冲突时保留未知，最新日期明确缺失也保留未知，不恢复更早标签。

现有 `industry_mapping.build_mapping()` 会跳过无法识别的新记录、保留更早有效标签；与新增导入器对“最新明确缺失”的处理不同。扩展资料应直接使用导入器已裁定的 `mapping`，不要重新把 `observations` 传给旧构建函数，否则会恢复旧标签并改变冲突处理。

文件 hash 证明文件内容一致，不能证明这些资料在过去已经存在。今天导出的“当前行业”只能从实际取得日期起用于研究；只有供应商提供真实的历史发布/采集记录，并在本地保存原件与获取时间，才可用于过去日期的实验。现有实验按信号日前一日截断资料，同日数据不进入此前的选股。

## 集成范围

`experimental_selection` 已接入 `--industry-master`，与 `--industry-history` 二选一，直接消费导入 JSON 的 `mapping`，保留冲突与未知，不重建历史映射。程序校验 schema、申万2021分类、逐行来源和hash，映射日期必须早于信号日；过晚记录保持未知，禁止把导入截止日当成每条记录日期。资料文件必须位于实验输出目录之外。映射后调用原来的 `attach_mapping()` 与一级行业选择器，并保留评分母集全覆盖及候选不足的硬检查。实验诊断同时记录原始CSV hash和导入JSON hash，便于复核使用的确切资料版本。

供应商分类版本、有效日期、发布时间和采集时间四项齐备后，才能检验历史行业变更。只有当前分类的文件可用于前瞻积累，不能补造历史分类。批量导入解决覆盖与请求数量问题，资料授权、字段真实性和历史可得性仍由原始来源决定。
