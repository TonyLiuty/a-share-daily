# 多 Agent 迭代工作流

项目采用“审计、展示、主线验收”三条职责线。Agent 可以并行提出修改，但只有主线验收通过后才进入生产脚本或策略配置。

## 角色

| 角色 | 负责内容 | 交付证据 |
|---|---|---|
| 策略审计 | 检查取数、预选、因子分数、行业约束和收益统计 | `docs/STRATEGY_AUDIT.md`、可复现测试、缺陷优先级 |
| 行业与报告 | 把行业、行业内标的、公司业务和风险放在同一条阅读路径 | HTML 验收、行业到标的映射、缺失数据标记 |
| 主线验收 | 合并改动、跑离线测试、检查数据边界和版本 | `validate_report.py`、`check_ui.cjs`、提交记录 |

## 迭代顺序

当前优先级是先保证策略输入可解释，再讨论权重调整：

1. 行业字段在选股前完成同源映射。覆盖不足时保留明确降级状态，并阻止把“未分类”当作行业约束已生效。
2. 保存数据源、行业映射版本、核心字段有效率和样本覆盖率。源切换时单独标记，避免跨日混比。
3. 收益统计按信号日记录参与数量、成熟数量和覆盖率，另列重复信号与独立股票日期。
4. 行业页先给行业表现，再列行业内观察标的、综合分、业务和风险；行业分类缺失时显示“行业未分类”。
5. 达到成熟样本门槛后，才做时间顺序样本外比较。候选权重必须与旧配置并行评估，保留版本和回滚路径。

## 稳定策略的验收标准

“稳定”不能由单日收益或少量命中判断。每次候选参数变更至少记录：

- 训练、验证、测试的时间区间；
- 1/5/20 日绝对收益、沪深 300 超额、最大回撤、胜率和盈利因子；
- 信号日覆盖率、重复信号比例、换手和成本敏感性；
- 行业集中度、最高行业占比和未分类占比；
- 东财主源与降级源的独立结果。

如果行业映射覆盖不足、核心字段大量缺失，或优势只出现在单一数据源和单一成本假设下，项目继续保持“研究观察池”定位，不调权重、不宣称稳定盈利。

## 当前状态

默认1.0.0生产策略保持不变；1.1.0实验策略使用独立输出和信号日前已经取得的申万一级资料，每行业最多2只，映射不能覆盖整个评分母集或选不足10只时停止。当前官方31表内5,275个代码中有84个分类冲突；对最近保存的1,000只行情代码，983只映射、12只冲突、5只缺失。待核对清单保留来源、标签和日期，不能凭名称推断或用今天资料回填历史。

实验加载已增加CSV原件与JSON的重新计算一致性检查，评估已拒绝混合策略版本、非法日期和代码。270条旧信号复算结果不变。行业公司列表已展示业务、得分强项和风险，桌面与手机验收通过。后续先取得能消除冲突的官方有效成分与变更证据，再积累冻结配置的前瞻实验；覆盖率尚未达到实验要求时不进入权重优化。

部署边界：日常自动任务仍使用已安装技能内的运行入口，仓库源码与该入口没有自动同步。已验证的展示改进可通过仓库离线重建查看；仓库提交与推送不代表生产入口已升级。后续部署需单列入口迁移、原版本备份、同输入结果对照和回退步骤，不把研究分支直接覆盖到已安装技能。
