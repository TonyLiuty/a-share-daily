# 行业标的阅读优化

## 目标与基线

2026-10-26 的实现按公司行业分组，行业行内只显示股票名称、代码与综合分。读者需要逐股展开详情，才能辨认主营业务、得分强项与具体风险。行业分组已与行情板块分类隔离，股票名称可跳转详情；这两个行为需要保留。

本轮验证的假设是：在行业分组内为每家公司增加三条短摘要，读者可以在展开详情前比较业务、因子与风险，且不会把摘要误读成行业行情。

## 可检验验收

| 场景 | 基线 | 成功条件 |
|---|---|---|
| 公司资料完整 | 名称、代码、综合分 | 每只股票显示主营、得分强项、风险三项；内容均取自该代码的已有摘要 |
| 主营和因子资料缺失 | 无提示 | 对应项明确写资料暂缺，保持股票与详情链接可用 |
| 风险摘要缺失、观察池有涨跌数据 | 无简析 | 展示已有20/60日涨跌数据，不补写新的风险判断 |
| 多只股票同行业 | 一行串联全部名称 | 公司分别占行，名称、代码、分数和短摘要结构一致 |
| 行情板块与公司行业同名 | 不拼接行情 | 继续不拼接跨分类涨跌 |
| 长摘要或特殊字符 | 只有名称转义 | 主营最多72字、强项最多56字、风险最多88字；截断加省略号；全部文本转义 |
| 手机屏幕 | 行业横向排列 | 公司摘要使用单列，原始资料保留在详情中 |

否决条件包括：摘要发生串股、行业行情错配、详情链接失效、缺失数据被填成判断、或摘要增长为重复长段。评分、策略、公司摘要来源和归档数据均沿用现有实现。本轮只调整呈现方式；模板和摘要长度仍可根据实际阅读反馈调整。

## 设计选择

保留现有蓝灰色金融报告配色：正文 `#213b50`、说明 `#596e7c`、链接 `#165e86`、边线 `#dce5ea`、浅底 `#f4f8fa`。沿用微软雅黑与现有字号层级。行业名作为组标题，公司名称与综合分在每行顶部，主营紧随其后，强项和风险分栏；窄屏改为上下排列。结构仅表达真实的“行业包含公司”关系，不增加装饰编号或动画。

## 验证记录

实施前已有9项行业UI回归测试通过。实施后12项测试全部通过，新增合成数据覆盖完整摘要、缺失、表格行情回退、跨代码隔离、长度限制和文本转义。`git diff --check`通过。2026-10-20归档报告离线重建通过，候选、基本面、配置、信号、收益曲线五个文件hash不变。浏览器在1440×1050和390×844通过搜索、详情跳转、打印恢复、图片加载、横向溢出和脚本错误检查；10只股票、10张图和7条事件与Markdown一致。行业区域桌面截图已人工检查，业务、强项与风险分列可读。
